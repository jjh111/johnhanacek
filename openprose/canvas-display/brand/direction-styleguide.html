I Palette Tokens

One role scale, seven palettes.

Every palette declares the same role tokens: the ink scale (--ink, --ink-2..5), the rule weights (--rule, --rule-mid), and the accent slots (--teal/--amber/--rust/--gold/--warn/--good as appropriate). The tables below are the reference for the canonical light and dark values. To compare and apply all seven, use the aspect catalog; this document stays on the canonical values, with the Surface switch previewing the canonical dark.

II Typography

Two families, six recipes, three monos.

The canonical type system is Kecal × mono. Six recipes (A–F) assign roles — display, body, eyebrow, em — to either Kecal or the active mono at specific weights and italics. Pick a mono via body[data-mono], pick a recipe via body[data-pairing]. The full 18-tile matrix lives in typography-pairings.html.

II.0 Face inventory

  • Kecal   8 weights (200–800), italic via fauxitalic. FungiType CDN.
  • IBM Plex Mono   300–700 + italic 400/500/600. Default mono.
  • JetBrains Mono   300–700 + italic 400/500/600.
  • Space Mono   400/700 + italic 400/700.

II.2 Cap-height normalisation

Kecal sits ~9% taller than the monos at the same nominal size. Use font-size-adjust: cap-height var(--cap-norm); on display elements (--cap-norm = 0.70) and font-size-adjust: ex-height var(--ex-norm); on body elements (--ex-norm = 0.50) to align top edges. Browser support: Chrome 127+, Safari 17+, Firefox 118+.

V.9 em · the accent (global rule)

Anything wrapped in <em> renders in Kecal 800 at 1em. Posture follows the data-accent axis: upright is the default, italic is the historical option. This is the writer's voice. Never apply <em> to a phrase the reader supplies (a quote, an aside). Pair with VII.1's do/don't before reaching for it.

VI Voice & Tone

One register, three sentences, three marks.

The brand voice is calm, specific, and unafraid of a short sentence. It names things by their nouns. Italic carries the writer's emphasis; the sidenote offers the reader's footnote. Below are the three sanctioned registers and a flat list of sample sentences in each.

Short · declaration
"Write the outcome. We run it."

Six words. The tagline register. Used on hero, primary marketing, the elevator pitch.

Spec · bang
"Billed by delivery!. If the outcome doesn't ship, no line."

Terms of art spoken plainly. The bang marker on the one word that carries the rule. One per page.

Editorial · italic
"Once, the week began with a scramble. Then the outcome was declared in a file."

Long form. Italic carries the pivot. No sidenote — the author still holds the line.

VI.1 More sample sentences

  1. Short. "OpenProse turns the file into a routine."
  2. Short. "The page reads the way a good analyst would have written it."
  3. Spec. "responsibility: the unit. cadence: the clock. outcome: the deliverable."
  4. Spec. "Every run is verified, signed, and archived. Seven years, by default."
  5. Editorial. "The standup happens anyway, but it is fifteen minutes shorter."
  6. Editorial. "The humanist computer is the insight that craft and machinery were never opposed."

VI.2 Voice rules

  • Italic is the writer; sidenote is the reader. They never share a phrase.
  • Maximum one bang (<sup class="sn">!</sup>) per page. If you reach for a second, the first is wrong.
  • Name things by their nouns. "Outcome", "delivery", "spec", "run", "brief" — not "thing", "stuff", "deliverable".
  • Short sentences earn long ones. If three sentences in a row are over 20 words, one must drop to under 8.
  • Never end a paragraph on chrome (badge, button, code-fragment) — only on prose.
VII Do / Don't

Five patterns, five mistakes.

These are the patterns that go wrong most often when a new operator picks up the system. For each: the correct application on the left, the misuse on the right, the reasoning underneath.

VII.1 em emphasis

Do

"The system is calm. The page does not announce; it arrives."

One italic per clause, on the verb or modifier that turns the sentence. The reader's eye lands on the meaning, not the typography.

Don't

"The system is calm. The page does not announce; it arrives."

Italic everywhere = italic nowhere. The eye stops tracking. Save em for the single word that, if removed, removes the sentence's pivot.

VII.2 The bang sidenote

Do

"Billed by delivery!. If the outcome doesn't ship, no line."

One bang per page, on the single load-bearing claim. If you find yourself reaching for a second, the first is wrong.

Don't

"Billed by delivery!. Verified!. Signed!. Archived!."

Four bangs = no bang. The bang is the brand's warning shot; reuse erases its weight. Use the numbered sidenote for the rest.

VII.3 Sidenote on chrome

Do

"The standup happens anyway, but it is fifteen minutes shorter3."

Sidenotes attach to prose — paragraph sentences, editorial H2/H3, document preview body. The reader is reading.

Don't

· Live3

Never on a badge, button, or the logotype. Chrome doesn't earn footnotes; the reader isn't reading chrome, they're scanning it.

VII.4 Italic and sidenote sharing a phrase

Do

"The machine handles the cadence. The prose handles the voice4."

Italic on one phrase, sidenote on a different phrase. Author voice and reader margin sit side by side, never on top of each other.

Don't

"The machine handles the cadence4."

Crossing them puts the reader's voice in the writer's mouth. The italic word is the author's; the sidenote is the reader's option to disagree.

VII.5 Colour as accent

Do

The page is loud only by the absence of colour.

Hierarchy is built from the five-step ink ramp on warm off-white. Distance from paper = importance. Teal is the writer's pivot, amber the rare "look up" — never both on the same phrase.

Don't

"Once, the week began with a scramble."

Three accents in one sentence = no accent. Red is for failure; teal is for the writer's pivot; amber is for one moment per page. Mixing them on the same phrase erases all three.

VII.6 Corner radius

Do

v λ.codex.0

Chrome (badge, button, code-fragment) uses sharp corners. The page reads as a document, not an app shell.

Don't

v λ.codex.0

Pill chrome reads as SaaS. The brand sits in the line between editorial and engineering; rounded corners pull it away from both.

IX Agent Integration

For the agent: read this section first.

The remainder of this section is addressed to an LLM that has been asked to render a page in any of the ten directions. If you are a human reader, treat this as the formal spec — everything above is the prose.

IX.1 How to produce a direction page

  1. Pick a direction (β γ δ ζ η θ λ μ ν ρ) from the aspect catalog and use its canonical recipe (palette/pairing/accent/mono/layout/mark) unless instructed otherwise.
  2. Link _tokens.css + _pairings.css. Never redefine palette or font-family in inline CSS — that breaks the cascade and the page can't be re-themed.
  3. Set the six data-* attributes on <body> (direction, palette, pairing, mono, layout, mark) — see VIII.
  4. Use role tokens (var(--type-display), var(--type-body), var(--ink), var(--paper), …) — never literal hex or font-family strings.
  5. Wrap any emphasis in <em>. The global rule from V.9 renders it correctly across every palette.
  6. For mark treatment (bloom / rain / ripple / physics / 3d / blackhole), include the appropriate snippet from _marks/<treatment>.html.
  7. Place a header comment per VIII.2 and tag every override with a dated // JH comment that quotes the source review verbatim. If any rule conflicts with a user instruction, ask before deviating.
