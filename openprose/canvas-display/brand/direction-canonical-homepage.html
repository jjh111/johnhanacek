I Responsibilities

A responsibility is a contract, not a prompt.

Write the future as a Markdown contract agents can run, review, and maintain. Not a chain of prompts.

01 / requires

It states what it requires.

Preconditions, up front.

What must hold before it runs: inputs, access, state. Nothing fires against an unmet world.

· preconditions
02 / maintains

It's judged on what it maintains.

The truth, kept current.

What must stay true while it runs. Each run is scored against it. Below the bar, the run holds; at or above, it ships.

· eval
03 / strategies

It's free in its strategies.

How it works, in prose, versioned.

The approaches an agent may take to meet the contract, declared in the source and reviewable as a diff.

· source.md
II Runtime

The runtime is the quiet half of the contract.

A small set of moving parts: picked up on cadence, scored against the contract, signed for the audit log. You write the responsibility; the runtime keeps its end.

→

Pickup · cadence

Picked up on the schedule the responsibility declares. Cron is a cadence, not a deployment. Manual runs hit the same path.

✓

Eval · threshold

Scored against the contract's success criteria. The bar is the responsibility's own, not a vendor default.

⊕

Sign · audit

Signed with the contract it satisfied. Anyone can reproduce it by reading the artifact. Retention is audit-grade, set per responsibility.

⤴

Improve · diff

Versioned as a diff against the last contract. Every change is a reviewable PR.

≋

Trace · visible

Traced end to end: input, prompt, evidence, eval. Open the trace to read what the runtime saw.

$

Bill · outcome

Billed by delivery, not by token. If the outcome doesn't ship, no line.
