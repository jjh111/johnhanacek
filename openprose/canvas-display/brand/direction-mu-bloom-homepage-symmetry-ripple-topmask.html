A program is a document with guarantees.

I · Paradigms

Three shifts in how software is shipped.

OpenProse is built on a small set of beliefs about what software is and how it should be promised. Three paradigms: a program is a document; a delivery is a verified outcome; the model is contracted, not asked.

01 / declare

A program is a document.

"Write the outcome. We run it."

Intent is executable. The spec is the source of truth — written, reviewed, version-controlled, signed. Every run is scored against it; every drift is surfaced. The page reads the way a careful analyst would have written it, and the runtime makes that page real.

· declarespec.yml
02 / verify

A delivery is a verified outcome.

"Every artifact carries the spec it was generated against."

Verification is the part that actually changed. Numbers were always automated; trust was not. OpenProse signs every delivery with the contract it satisfied — a year from now you'll know what was promised, what was produced, and what evidence was kept.

· verifycontract.sig
03 / contract

The model is contracted, not asked.

"Billed by delivery. If the outcome doesn't ship, no line."

A prompt is a request. A contract is a commitment. The runtime holds delivery when the spec isn't met; the operator gets the artifact only after the eval passes. The model carries weight inside the page — it doesn't get to set the page's purpose.

· contractdelivery.proof
II · Runtime

The runtime is the quiet half of the page.

A small set of moving parts — picked up on cadence, evaluated against the spec, signed for the audit log. The operator writes prose. The runtime keeps its end of the contract.

→

Pickup · cadence

Programs run on a schedule the document declares. Cron is a cadence, not a deployment. Manual runs hit the same path.

✓

Eval · threshold

Each run is scored against the spec's success criteria. Below threshold holds the artifact; above, signs and ships.

⊕

Sign · audit

Every delivery carries the spec it satisfied. Reproducible by reading the artifact. Audit-grade retention configurable per program.

⤴

Improve · diff

Refinements land as a diff against the previous spec. The contract is versioned; every change is a reviewable PR.

≋

Trace · visible

Each run produces a trace: input, prompt, evidence, eval. Open the trace to read what the runtime saw.

$

Bill · outcome

Billed by delivery, not by token. If the outcome doesn't ship, no line. The pricing matches the contract.

III · Contract

Write your first program.

Fifteen lines of YAML. Pick it up on cadence. Verify against the spec. Sign the delivery. The runtime keeps the rest of the schedule out of your week.
