§1 · Foundation

OpenProse — Direction β · teal.

Tufte, in mono, with Kecal in the accent seat, recolored from the η · ORGANISM · mono · teal palette. The reading face is IBM Plex Mono at body weight; emphasis is Kecal extrabold upright in teal #3a7a6a; chrome labels are Kecal medium. The page sits on fog cream #f5f0e8 over warm brown-black #2a2520 ink. The warm complement golden amber #c49a5c is the rare "look up" accent — used at most once per page on the load-bearing claim. Emphasis is the sidenote — a numbered marginal note that the reader can opt into. There is no highlighter; legacy .hl markup renders as a dotted teal underline so older pages still read.

§1.1 · Design Rationale

Why this direction, in one paragraph.

OpenProse is sold to operators who already trust documents. The β direction takes Tufte's reading discipline — narrow column, off-white paper, ink ramp, marginal sidenotes — and rebuilds it in monospace. IBM Plex Mono is the body face because the product is half spec, half essay, and the mono keeps both registers visually honest. Kecal sits in the accent seat because its extrabold static carries the emphasis a synthesised slant would otherwise lose. There is no accent colour: colour competes with the sidenote, and the sidenote is the brand. A page in this direction should look like a typewriter that read books.

§2 · Colour tokens

Fog paper, warm ink, teal, and a golden amber.

The palette is the η · ORGANISM · mono · teal system applied to the β Tufte structure. Fog cream paper #f5f0e8 carries the page; warm brown-black #2a2520 carries the ink ramp at four alpha-stops. Three accent families do the editorial work: teal #3a7a6a handles the writer's pivot (em emphasis, section markers, hairline rules, in-prose links); golden amber #c49a5c is the warm complement reserved for the rare "look up" moment (one phrase per page maximum); and editorial red #c0392b is the fail / needs-attention signal — failed evals, broken contracts, the badge that says "this needs you." Never mix red with teal in the same phrase; they're independent registers. Each accent lands with three brightness siblings (canonical / deep / muted-or-soft) plus tint & faint washes for backgrounds. Anything not in this table is forbidden.

§5 · Layout primitives

Two containers, two measures, one breakpoint.

The page sits in one of two outer containers — --wide for grid sections (palette, type, applications) and --measure for prose (editorial pairing, sidenote-bearing copy). The ideal line length is 62ch — set on .lede and any long-form paragraph.

6.9 · em (the accent)

The brand-wide accent rule. Anything wrapped in <em> renders in Kecal 800 upright at 1em. Upright is the default (c_a965130b); italic is the historical option. This is the writer's voice. Never apply <em> to a phrase the reader supplies (a quote, an aside).

The system is calm. The page does not announce; it arrives.

The system is <em>calm</em>.

em {
  font-family: 'Kecal', sans-serif;
  font-style: normal;   /* upright accent · c_a965130b */
  font-weight: 800;
  font-size: 1em;   /* cap-height match to Plex Mono */
  letter-spacing: 0;
}

6.11a · sidenote skim + hot · underline markers

When the prose can carry the sidenote on the line itself, the β direction silences the legacy highlighter into a hairline underline. Two variants: skim for a numbered glance, hot for the page's load-bearing claim.

Sidenote hot "Billed by delivery!. If the outcome doesn't ship, no line."

§7 · Voice & tone

One register, three sentences, three marks.

The brand voice is calm, specific, and unafraid of a short sentence. It names things by their nouns. Italic carries the writer's emphasis; the sidenote offers the reader's footnote. Below are the three sanctioned voices and a flat list of sample sentences in each.

Short · declaration
"Write the outcome. We run it."

Six words. The tagline register. Used on hero, primary marketing, the elevator pitch.

Spec · bang
"Billed by delivery!. If the outcome doesn't ship, no line."

Terms of art spoken plainly. The bang marker on the one word that carries the rule. One per page.

Editorial · accent
"Once, the week began with a scramble. Then the outcome was declared in a file."

Long form. Italic carries the pivot. No sidenote — the author still holds the line.

More sample sentences

  1. Short. "OpenProse turns the file into a routine."
  2. Short. "The page reads the way a good analyst would have written it."
  3. Spec. "responsibility: the unit. cadence: the clock. outcome: the deliverable."
  4. Spec. "Every run is verified, signed, and archived. Seven years, by default."
  5. Editorial. "The standup happens anyway, but it is fifteen minutes shorter."
  6. Editorial. "The humanist computer is the insight that craft and machinery were never opposed."
§8 · Do / Don't

Five patterns, five mistakes.

These are the patterns that go wrong most often when a new operator picks up the system. For each: the correct application on the left, the misuse on the right, and the reasoning underneath.

1 · em emphasis

Do

"The system is calm. The page does not announce; it arrives."

One accent per clause, on the verb or modifier that turns the sentence. The reader's eye lands on the meaning, not the typography.

Don't

"The system is calm. The page does not announce; it arrives."

Accent everywhere = accent nowhere. The eye stops tracking. Save em for the single word that, if removed, removes the sentence's pivot.

2 · The bang sidenote

Do

"Billed by delivery!. If the outcome doesn't ship, no line."

One bang per page, on the single load-bearing claim. If you find yourself reaching for a second, the first is wrong.

Don't

"Billed by delivery!. Verified!. Signed!. Archived!."

Four bangs = no bang. The bang is the brand's warning shot; reuse erases its weight. Use the numbered sidenote for the rest.

3 · Sidenote on chrome

Do

"The standup happens anyway, but it is fifteen minutes shorter3."

Sidenotes attach to prose — paragraph sentences, editorial H2/H3, document preview body. The reader is reading.

Don't

· Live3

Never on a badge, button, or the logotype. Chrome doesn't earn footnotes; the reader isn't reading chrome, they're scanning it.

4 · Italic and sidenote sharing a phrase

Do

"The machine handles the cadence. The prose handles the voice4."

Italic on one phrase, sidenote on a different phrase. Author voice and reader margin sit side by side, never on top of each other.

Don't

"The machine handles the cadence4."

Crossing them puts the reader's voice in the writer's mouth. The accented word is the author's; the sidenote is the reader's option to disagree.

5 · Colour as accent

Do

The page is loud only by the absence of colour.

Hierarchy is built from the five-step ink ramp on warm off-white. Distance from paper = importance.

Don't

"Once, the week began with a scramble."

No editorial red. No teal. No mid-blue. Tufte trusts the page; the moment colour enters, the page no longer reads as Tufte.

§9 · File conventions

One file per direction, one header, one comment style.

Each brand direction lives in a single self-contained HTML file. No external CSS, one inline <style> block, one optional inline <script> for the pretext layout. Web fonts come via @import in CSS or @font-face for self-hosted faces.

Naming pattern

Files in JHWorking/brand/ follow the pattern:

direction-{greek-letter}-{slug}.html

examples
  direction-alpha-editorial.html
  direction-beta-tufte.html
  direction-beta-tufte-mono.html              // fork: changed body face to mono
  direction-beta-tufte-mono-kecal.html        // fork: replaced sans/accent with Kecal
  direction-beta-tufte-mono-kecal-styleguide.html  // THIS FILE: documentation fork

A fork that changes one decision should add one slug segment, in order of cascade. Forks accumulate left-to-right; the latest decision is the rightmost segment.

Header comment template

Every file opens with a block comment that names the direction, its DNA, and its implementation strategy. Template:

/* ============================================
   DIRECTION {GREEK} · {NAME}
   {One-line tagline.}

   DNA: {Body face} body, {Sans face} labels, {Mono face} specs.
   {Paper hex}, {ink scale shape}, {colour policy}.
   Emphasis is {the brand's emphasis primitive}.

   Implementation: {what was inherited from a parent direction
   and what this fork overrides}.
   ============================================ */

JH comment-tag convention

Decisions, overrides, and revisions are tagged inline with a date-stamped JH comment. The format is:

// JH YYYY-MM-DD — short rationale

examples
  // JH 2026-05-13 — "shrink title serif to match top of mono used for Open."
  // JH 2026-05-07 — italic +20% drop to +14% over Tufte's narrow column
  // JH 2026-05-18 — replace garamond and inter with styles of kecal

The quotation marks around a JH note mean the words inside are pulled verbatim from a review JSON. No paraphrase. If the reviewer didn't say it that way, don't say they did.

Section organisation

A direction file flows in this order, with section IDs that match this style guide:

  hero            section.hero
  palette         section#palette
  type            section#type
  highlighter     section#highlighter      // β: sidenote section
  pairing         section#pairing
  variations      section#variations
  ui              section#ui
  applications    section#applications
  voice           section#voice
  colophon        section.colophon

CSS within the <style> block follows the same vertical order: reset → tokens → base → hero → sections → palette → type → … → responsive → override blocks. Each override block (parent → fork → fork) has its own banner comment.

§10 · Agent integration

For the agent: read this section first.

The remainder of this section is addressed to an LLM that has been asked to render a page in this direction. If you are a human reader, treat this as the formal spec — everything above is the prose.

How to use this style guide

If you are an agent producing HTML in this direction, do the following. One: copy the :root token block from §0.2 into your file verbatim. Two: import the same fonts (Kecal via @font-face, IBM Plex Mono via Google Fonts). Three: set body to --mono at 0.94rem / 1.7 line-height. Four: wrap any emphasis in <em> — the global rule in this guide will render it correctly. Five: never introduce a colour token that is not in §2. Six: never apply .hl markup as a new pattern; reach for <sup class="sn"> instead. Seven: place a header comment per §9, and tag every override with a dated // JH comment that quotes the source review verbatim. If any of these conflict with a user instruction, ask before deviating.
