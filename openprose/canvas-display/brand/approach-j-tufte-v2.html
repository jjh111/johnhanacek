Responsibilities replace workflows

A responsibility is a declarative contract: what needs to happen, what good looks like, where results go. No orchestration code. No imperative DAGs. The session is the runtime.

1. Define

responsibility: name: revenue-report schedule: weekly/monday deliver_to: #finance-ops source: stripe: last 7 days quickbooks: current period
Definitions/wk 42

2. Contract

contract: completeness: all_sources accuracy: <2% variance freshness: <15min lag format: markdown_table escalate_if: variance: >5% source_down: >30min
Contract met 99.4%

3. Deliver

delivery: monday 08:00 UTC → #finance-ops ✓ completeness: all_sources ✓ accuracy: 0.3% variance ✓ freshness: 2min lag → "Revenue report delivered. See thread for details."

Open source, open architecture

OpenProse is MIT-licensed.1 The runtime executes inside the agent session — no external dependencies, no library lock-in, portable across any Prose Complete system. You can self-host it, like Terraform. Most teams prefer we run it for them, because reliability at 99.7% on-schedule is worth paying for.

The architecture inverts the conventional agent framework model.2 Where LangChain, CrewAI, and AutoGen orchestrate from outside using imperative code, OpenProse runs inside the session. The session is the runtime. Responsibilities are declarative contracts, not task sequences. Execution latency has dropped from 7.1s to 4.2s median over the past year.

This distinction matters because declarative systems compose.3 You can add a responsibility without understanding the existing ones. There is no dependency graph to manage, no execution order to reason about. Each responsibility is independently evaluated and independently delivered.
