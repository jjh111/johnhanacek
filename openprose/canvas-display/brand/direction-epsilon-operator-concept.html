Running OpenProse on a real Monday.

Twelve responsibilities, one operator, forty buildings. This is the runbook we wrote so the new hire could cover for me when I'm in Building 14 looking at a boiler.

Maintained by Sarah K. Last touched 2026-05-04, 09:14 ET running

PROC 01 Adding a new responsibility

When the team needs a new piece of work to run on cadence, write the spec first. The spec is the contract — everything else is implementation. Do not start by sketching the prompt.

  1. Open ~/responsibilities/ and copy _template.prose to your-thing.prose.
  2. Fill in requires:. List every input by its source: API name, file path, repo ref. If you can't list it, the spec isn't ready.
  3. Fill in ensures:. Write what must be true after a successful run, in plain language. Aim for 2–4 clauses; more than 5 means you're describing the prompt instead of the contract.
  4. Set cadence:. Don't be cute. Mondays @ 09:00 ET means Mondays at 09:00 Eastern, every Monday, forever, until you change the file.
  5. Run op run your-thing --dry-run. Read the diff between what you specified and what the runtime drafted. Iterate the spec, not the prompt.
  6. When the dry-run scores ≥ 0.85 three times in a row, sign the file and commit it. From then on, the runtime owns the cadence.
Sarah's rule If you find yourself rewriting the prompt, you're rewriting the wrong file. Close the editor. Walk to the kitchen. Come back and rewrite the spec.

PROC 02 Holding a delivery when the eval drops

If the runtime scores a responsibility below the contract threshold, it holds delivery and pages on-call. Don't override the hold to ship a bad draft. The contract is the contract.

  1. Open the alert. Read the op why output before doing anything else — it almost always names the cause.
  2. Decide: is the spec at fault, or the inputs? Spec at fault means the contract was ambiguous; inputs at fault means a dependency failed.
  3. If the spec is at fault, schedule a 15-min spec review with whoever owns the responsibility. Patch in the next push, not now.
  4. If the inputs failed, check the upstream — usually the utility API or the warehouse. Re-run with op run --retry once the upstream is green.
  5. If you can't decide, hold the delivery and let the on-call rotation pick it up at 09:00. Mondays at noon are not for spec rewrites.

FAQ The questions everyone asks

Why do you keep the standup if the digest already arrived?

Because the standup was never about the digest. It was about looking at each other on a Monday morning and arguing about which boiler was making the biggest noise. The digest let us stop pretending the meeting was about the digest.

If you skip the meeting because "the digest already arrived," you'll re-create it under a different name within six weeks. Trust me on this.

The runtime drafted a paragraph I disagree with. What now?

Edit the draft — but more importantly, edit the spec with what you learned. The runtime will keep drafting that paragraph until you tell it not to. The brief gets smarter on edits, not on overrides.

If you find yourself rewriting the same paragraph two weeks in a row, the spec is wrong. Don't be a hero; rewrite it.

— sk · last touched 2026-04-30
Can I add a responsibility for a one-off thing?

You can. You shouldn't. Responsibilities run on cadence. If something is one-off, it's a request, not a responsibility. Send it to me; I'll write it as a real prompt and ship it manually.

Exception: if "one-off" means "we'll need this every time we onboard a new building," that's a cadence of "on-event." Make it a responsibility. cadence: on-event(new-building).

— sk · last touched 2026-04-12
Why is the weather API rate-limited at 0.94?

Because someone (it was Jamie, but he's apologized) made tenant-anomaly-watch hit it once a minute for a week in March before we noticed. We're now on probation with the vendor until June.

The rate cap will go back to 1.0 after the next billing cycle. Until then, expect 6% of weather lookups to fail. The runtime handles it, but if you see the digest cite "weather data partial" three times in a row, page me.

— sk · last touched 2026-03-31
Why aren't the boilers in any responsibility?

Because a boiler doesn't have an API. It has a serial number, a service log in a folder somewhere, and a person named Frank who knows what's wrong with it. We're working on getting the service logs into the warehouse; until then, boilers are managed the old way.

This is fine. Not everything has to be a responsibility. The literary computer is for things that happen on cadence. Frank is not on cadence.

— sk · last touched 2026-05-01
What do I do if Sarah is out and something fails?

Page Jamie first. If Jamie is also out, the on-call rotation is in ~/responsibilities/_oncall.prose. The runtime keeps that one running too — it would be a little embarrassing if our on-call schedule wasn't itself a responsibility.

If everything is on fire, the answer is almost always: hold the delivery, let it go to next cadence, and rewrite the spec on Tuesday morning. Nothing has to ship on Monday. The contract says it ships or the line refunds.

TBL 01 Common failures · what to do

Most weeks, nothing here triggers. When something does, this is the order to try things.

SymptomWhat to do
Eval score regressed for two weeks running. Open the spec. Compare the latest draft to v(n−2). Ten times out of nine the spec needs tightening. Run op diff --spec to see what's drifted.
Delivery didn't ship at the appointed cadence. Check op log --tail and op why. If the runtime held the delivery, that's working as designed; if it crashed, page on-call.
Recipient says the brief is "AI-flavored". Tighten the tone: clause. "executive-friendly" is too vague; try "no metaphors, no hype, no exclamations". Run dry until the eval climbs back.
A responsibility you set up last quarter drifted. Drift is normal. Specs need pruning every 8–12 weeks; the runtime gets very good at edge cases that no longer matter. Cut clauses that haven't fired in 30 days.
Someone wants to add a "just this once" override. Don't. Make them sign a one-shot prompt request via op manual. Override paths corrupt the contract.
